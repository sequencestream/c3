# 0031 — 自动化队列的确定性调度内核:tick 对账 + 事件降级为提示 + 状态重推导

- **Status:** accepted
- **Date:** 2026-07-31

## Context

自动化队列此前是一个**只被 `run:settled` 事件推动的内存状态机**(`features/intents/workflow.ts`)。
它能跑通顺利路径,但「一有问题就卡住,没办法自动往下执行」。根因不是缺少智能,而是编排器缺三样
纯工程能力:**幂等的重新对账、失败隔离、决策可观测**。具体卡死点:

1. **五处 `void this.hooks.runDevTurn(...)` 没有 `.catch`。** launch 一旦抛异常,`run:settled` 就永远
   不会到来,队列静止 —— 异常被丢在地上,没有任何东西记录它。
2. **`_processing` 守卫直接丢弃并发到来的 settle。** 事件是唯一真相,却会被丢。
3. **`awaiting_gate` 只靠阻塞会话的 settle 唤醒。** 阻塞会话若已死(进程崩溃/服务重启),
   settle 永不到来,闸门永久关闭。
4. **`fail()` 一条意图失败即停整条队列。** 一条坏意图连坐全部无关意图。
5. **控制器纯内存。** 服务重启即丢全部状态,队列静默变回 `idle`。
6. **无任何执行日志。** 用户无法回答「现在为什么不动了」。
7. **SDD 未批准的意图被静默跳过,队列却显示 `done`** —— 误导性成功。

这七条有一个共同形状:**系统把「事件到达」当作前进的必要条件**。凡是必要条件,缺失就是死锁。

## Decision

把队列的驱动方式换成**定时全量对账 + 事件合并标脏**,并把调度纯逻辑提取为一个 kernel 模块。

### 1. 事件降级为提示(hint),不再是驱动力

生命周期事件**不携带决策依据**,只把 workspace/intent 放进一个**合并式脏集**,请求「再看一眼」。
重复标脏合并为一次;内核处理期间到达的标脏**留待下一轮,不得丢弃**。

因此总线**不需要持久化、不需要重放、不需要投递保证**:丢一个事件最多造成一轮(10s)延迟,
不再造成永久卡死。这也让 `_processing` 守卫的「丢弃」语义从缺陷变成正确 —— 丢的是**提示**,
不是**真相**。

### 2. 状态重推导,而不是持久化重型 FSM

每一轮对账从**事实**重新推导该做什么:意图账本快照 + 活跃 run 的存活探测 + 一小撮持久化的
单意图调度元数据。运行阶段、当前会话、闸门结果一律**不存**。

只持久化四类无法被重推导的东西:连续失败次数、退避截止、park 标记与原因、防自激冷却
(外加工作区级的启停意愿,使重启后能恢复用户真正要的状态)。丢一行最多多重试一次。

代价:牺牲完整 FSM 历史。**历史解释由独立的 `queue_decision_log` 承担**,按 tick/intent 记录
选择的动作、被哪个闸门挡住、拒绝理由、尝试/退避计数与下次唤醒时间。它**刻意不复用**
`automation_execution_logs` —— 后者按「一次自动化执行」计量,粒度对不上。

### 3. 内核 / 装配分层(ADR-0009 单向边界)

- `kernel/queue/` —— **纯**调度逻辑:`reconcileQueue(input) → { actions, decisions, nextWakeupAt }`,
  无 I/O、不改输入、完全确定性,不 import `features/` 或 `transport/`。
- `features/intents/workflow.ts` —— 装配:采集事实快照、持久化、启动 run、写决策日志、执行动作。
- `wiring/` —— 事件订阅、广播、WS 处理、启动对账与 tick 循环的组装。

确定性是可测试性的前提:每个调度规则都能用「固定快照 + 固定时钟 → 期望动作」断言,不需要
计时器、mock 或真实 run。

### 4. 失败隔离取代整队停止

**所有内核发起的 run 都被 await 并捕获异常**(launch / resume / attach / continue / lint 修复)。
一次失败只计为**那一条意图**的一次尝试:指数退避(30s 起,逐次翻倍,上限 15 分钟),
**连续第 3 次进入 park**。

park 的关键性质:**park 不是 `done`**。依赖被 park 意图的下游继续被依赖闸门挡住,
**既不跳过也不放行**;无依赖关系的其他意图继续参与选择。park 隔离一次失败,
它从不打开一条绕过失败的路。

### 5. 三个入口,一个幂等 pass

定时 tick、事件标脏、服务启动进入**同一个** reconcile 入口。相同输入重复执行不得产生重复
launch、重复失败计数或重复人工待办。防自激:内核发起的 run 带稳定 origin tag,加**每意图
冷却窗口**,阻止 tick 与事件紧邻造成的重复 launch。

## Consequences

**得到**

- 队列不再因为「某个事件没来」而卡死。异常、丢事件、死会话、服务重启都在下一轮被吸收。
- 一条坏意图不再连坐整条队列。
- 「现在为什么不动了」有确定答案,并可在队列页面逐条查看。
- 调度规则可用纯函数测试覆盖,不再需要拼时序。

**付出**

- 固定 tick 带来少量空转开销(每 workspace 每 10s 一次快照 + 一次纯计算)。
- **RM-A9「受监督而非无人值守」的体感改变**:队列不再为一条意图整体停摆。这是有意的 ——
  但必须诚实记录:依赖链下游仍受阻,不会被越过。
- 单意图调度元数据是新的持久化面(三张小表),需要随 schema 演进维护。

## 明确未改变的东西(硬闸门)

RM-A12 全局并发闸门、依赖闸门 + worktree 模式下「依赖 PR 已 merged」、SDD `specApproved` 闸门、
`AskUserQuestion` / pendingQuestion 守卫(RM-A11)、续跑预算、workspacePath 工具闭包绑定 ——
**一律未放宽**。

**未新增任何自动标 `done` 的路径**(RM-R9 例外范围不扩大)。

**权限决定永不超时、永不自动作答**(C-SEC-3)。有窗口的是**队列的等待**:超窗时队列 park 该意图
并推一条 `wait-user-involve` 待办,而**运行保持存活、不被中止**。这一区分是本 ADR 最容易被误读的
地方,也是最不能妥协的地方。

`start_workflow` / `stop_workflow` / `workflow_status` 的消息形状与含义**向后兼容**,只替换背后
引擎;队列详情走**新增**的独立读契约,不把逐 tick 日志塞进 `WorkflowStatus`。

## 主动放弃的替代方案

1. **持久化重型 FSM 表。** 每个阶段都落库、按事件迁移状态。放弃原因:状态与事实之间会漂移,
   而漂移的修复手段又只能是……对账。既然终点是对账,不如直接以对账为唯一机制。
2. **让 LLM 直接驱动队列。** 放弃原因:那只会把「确定性地卡住」换成「不确定地卡住」,
   且更难排查。调度是纯工程问题,不是判断问题 —— 判断已经由完成判定器和检查点共识承担。
3. **给事件总线加持久化 + 重放。** 放弃原因:成本高、语义复杂,且解决的是错误的问题 ——
   真正的修复是让系统**不依赖**任何单次事件送达。
