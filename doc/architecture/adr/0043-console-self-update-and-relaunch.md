# 0043 — 控制台自更新:服务端编排下载,按运行形态移交重启

- **Status:** accepted
- **Date:** 2026-08-13

## Context

c3 已经知道有新版本：一个进程内的检查器每天问一次 GitHub 最新发行版，与编译期钉入的 `VERSION` 比较，把结果播给所有连接，顶栏渲染一个蓝色胶囊。胶囊只是个外链。

真要装上，用户得回终端跑 `c3 upgrade`（下载、校验、原子替换二进制），再跑 `c3 restart`（重启 OS 服务或 `--daemon` 进程）。两条命令都存在、都能用，但它们要求用户离开浏览器、知道自己是哪种运行形态、并且记得升级完还有第二步。实际结果是：一台机器上的 c3 停留在装那天的版本。

桌面渠道已经把这条链走通了：Tauri 壳有完整的「检查 → 确认 → 下载 → 校验 → 退出 → 助手安装 → 重启」状态机，版本事实与传输委托给 sidecar 的回环 API。CLI 渠道缺的正是这个编排层。

三个问题需要决策：

1. 下载与状态机放在哪一侧？
2. 二进制什么时候替换？
3. 一个进程怎么重启它自己？

## Options considered

**下载与状态机的归属**

- **A. 扩桌面壳的 `/api/update/*`，让浏览器直接下载。** 被否决。浏览器拿到的字节要交回服务端才能落盘，多一次穿透；而且状态会分散在每个标签页里，两个开着的控制台会各自下一份。
- **B. 服务端持有唯一状态机，浏览器只是它的一个视图。** **采纳。**

**替换时机**

- **C. 下载完立刻替换，重启只是重启**（`c3 upgrade` 今天的形态）。被否决。用户可能永远不点重启，此时磁盘上是新版本、内存里是旧版本，从终端敲 `c3` 得到的又是另一个版本——一个没人要求过的中间态。
- **D. 校验通过只落暂存区，替换发生在按下重启的那一刻。** **采纳。**

**自重启**

- **E. 复用 `runRestart()`。** 被否决。它面对的是**别的**实例：daemon 分支会 SIGTERM `c3.pid` 里的那个 pid——正是调用者自己，然后再也执行不到重启那一步。
- **F. 一律派生助手进程**（桌面渠道的做法）。被否决为唯一方案：systemd 场景下助手在本单元 cgroup 内，会随单元一起被杀。
- **G. 按运行形态分策略。** **采纳。**

## Decision

- **状态机在服务端，且只有一份。** 浏览器发三条消息（开始 / 应用 / 取消），服务端广播快照。前端不本地预测、不镜像。快照随 `ready` 握手播种，所以新开的标签页立刻看到在途下载。
- **下载与校验复用升级内核**（`upgrade-core.ts` / `upgrade.ts`）。为此从 `runUpgrade` 抽出两个机械步骤——`stageRelease`（下载 → 校验 → 解包，不碰任何已安装的东西）与 `applyStaged`（唯一一次改动），`runUpgrade` 改为组合它们。CLI 的语义与退出码契约不变；两个入口共用同一套完整性规则与同一套平台替换策略。
- **`ready` 之前不碰安装位置的二进制。** 下载只花带宽：磁盘与运行中的进程始终一致，坏包或中断不会留下任何需要解释的中间态。
- **重启按运行形态移交**：systemd 用 `systemctl --user restart --no-block`（`systemctl` 子进程随本单元被杀，只有入队的 job 活得下来）；launchd 靠 `KeepAlive`，干净退出即重启；`--daemon` 与 Windows 计划任务交给脱离父进程的助手（`c3 update-apply`），它等旧 pid 退出后再替换与拉起；终端前台就地派生后继进程，继承同一终端与进程组。
- **能力门 fail-closed**：桌面壳托管、dev/解释器运行、包管理器前缀、目录不可写四种情形一律不自更新，并把原因作为闭集 token 报给前端。
- **动作限管理员，状态给所有人。** 重启会断开每一个连接。

## Consequences

- 顶栏的死链（README 里并不存在的 `#upgrade` 锚点）被一个真正能用的控件取代，不能自更新时才退回外链，且指向发行页。
- 一台按默认方式安装的 c3 会自己保持在最新版本一次点击之内。代价是发现新版后会静默下载约 70–80MB；下载失败不惩罚任何东西，下一轮检查重试。
- 前台形态可以一键重启了，副作用是父进程退出后 shell 提示符提前返回（后继进程仍在同一终端输出，Ctrl-C 仍然有效）。
- 助手进程是同一个可执行文件的隐藏子命令，因此不新增分发物；它与桌面壳的更新助手是同一形状的两份实现，各自服务不同的产物粒度（单二进制 vs 完整应用包）。
- 暂存区落 `<c3Home>/update-staging/` 的普通文件而非数据库：助手是独立进程，不该为读一条记录去开 SQLite。因此本决策不引入任何 schema 变更。
