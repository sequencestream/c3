# 0046 — IM 聊天机器人:进程内长连接 + 外发授权四重表达

- **Status:** accepted
- **Date:** 2026-08-20

## Context

c3 至今只有一条人机通道:浏览器经 `/ws` 连上本地进程。把 agent 能力接进飞书这类办公 IM,意味着
两件此前没有发生过的事——c3 第一次接受来自第三方云的入站消息,也第一次主动把 agent 的产出发往
本机之外。

后者正撞在宪法的边界基线上:「在未经用户明确授权的情况下,把用户的代码、凭据或工作数据送往本机
之外」是未经 ADR 禁止跨越的一条线。它禁的不是外发本身,而是**未经明确授权**的外发,因此这条裁决
必须回答「明确授权」在产品里长什么样,而不是只声明一句允许。

C-SEC-4「不碰凭据」同样需要一次解释。它约束的是**agent 供应方**的凭据——各 vendor CLI 自己拥有
认证权,c3 不插手。IM 应用密钥不属于这一类:它是用户自己的第三方集成凭据,与 `AgentConfig.apiKey`
同类,后者早已由 c3 加密持有。

还有一个与安全无关但同样要在此定死的问题:群聊里没有人能回答权限对话框。一个会在敏感工具上挂起
等待的会话,接到 IM 上就是一条永不回复的消息。

## Options considered

- **A. 外部转发进程走已有 `POST /mcp`** —— 被否决。c3 不引入任何 IM 代码,由用户自建桥接进程持
  `c3k_` key 调用。它把外发边界移到一个 c3 无法约束的进程里:审计、内容守卫、默认关闭三条凭据全部
  落空,而边界依然被跨越了。且外部 MCP 的授权范围绑定工作区,与「机器人不绑工作区」直接冲突。
- **B. Webhook 回调** —— 被否决。要求 c3 公网可达并配置回调地址与验签,与「以本地进程运行、易于
  自托管」的价值观相斥,把一个本地工作台变成必须暴露的服务端。
- **C. 只出不进(单向通知)** —— 被否决。跨越外发边界的合规成本一分不少,换回来的只有通知,满足不了
  「群里对话驱动 agent」这个真正的诉求。
- **D. 给 work session 一个发消息的 MCP 工具** —— 被否决。外发变成模型的自主行为,每一次都无法预先
  授权,与 C-SEC-2「授权前置」冲突。
- **E. 进程内集成 + 出站长连接** —— **选定**。c3 作为客户端主动连出,不需要公网可达,外发的每一个
  环节都留在 c3 自己的约束之内。
  选定 E 之后,与飞书 SDK 的关系另有三个选项:

- **E1 完全自行实现长连接** —— 被否决。飞书长连接不是普通 wss:先换取连接地址,再走私有的 protobuf
  二进制帧(含分片重组与 ACK),其 schema 只嵌在各语言 SDK 内、无公开文档。自实现等于逆向一个不承诺
  兼容的二进制协议并长期背负它。
- **E2 引入 SDK 的高层封装(`LarkChannel`)** —— 被否决。它确实自带「必须 @ 机器人」「入站去重」
  「同会话串行」「出站分片」等便利,但这些恰恰是**平台无关**的策略,放进飞书适配层就等于给钉钉、
  企微各写一遍。更硬的理由是体积:实测它把发布产物从 2.8 MB 推到 8.2 MB,因为它持有全量 OpenAPI
  客户端。
- **E3 只取 SDK 的长连接,出站自行实现(选定)** —— 用 `WSClient` + `EventDispatcher` 收事件,发消息与
  令牌获取走 c3 自己的出站 HTTP 通道。实测只增加 0.7 MB:难以自实现的那部分(protobuf 帧)保留,
  真正臃肿的那部分(全量 OpenAPI 表)不引入。附带三个好处:出站因此遵守「服务端出站一律走统一通道」
  的既有约定、不必验证第三方 axios 实例的代理注入、平台无关的策略留在中性层供后续平台复用。

## Decision

### 唯一出站守卫与封闭外发类别

一切 IM 外发必须经过**唯一出站守卫**（`sendGuarded` / `sendGuardedBroadcast`）。入站最终回复、
固定控制提示、绑定提示与 L0 事件模板可以有不同的触发器,但都必须把结构化目标与内容交给同一守卫;
「唯一」以发送权限、裁决和审计是否统一判断,不以 `send` 调用点数量判断。provider 的原始发送能力只
注入守卫内部;supervisor、事件订阅器与模板渲染器均拿不到可直发 sender。

封闭外发类别:

- **最终 assistant 文本** —— 一轮回合结束时由 viewer 累积的 assistant 文本;工具调用、工具结果、
  思考过程、文件内容、会话转录不进外发路径。
- **已注册固定提示** —— 超时/阻塞/错误/忙碌/入站拒绝/凭据拦截等 `fixed_notice`,以及绑定控制
  `binding_notice`。
- **L0 事件模板播报** —— 服务端强类型 `im:broadcast_candidate` 触发的 `broadcast_template`;只
  接受七种已注册事件、严格模板与字段白名单;不接受 agent 文本、事件自由文本或任意载荷。

守卫在每次实际投递前重新读取事实,并按固定顺序执行:机器人启用且外发配置哈希与确认绑定一致;目标
仍过群/私聊白名单(绑定提示保留 ADR-0049 窄豁免);内容属于封闭类别;凭据形状检测与截断;统一外发
审计。守卫或审计不可用时失败关闭。

L0 只订阅进程内 `im:broadcast_candidate` 强类型主题,与模型可发布的通用 `event` 主题完全隔离。
通用 `publish_event` 无论声明何种 type 或 metadata,都不能触发 IM 播报。

L0 事件模板字段白名单:事件类型、对象类型、对象 ID、对象标题、规范状态/原因码、受限数字计数、
发生时间、只读 Web 深链。禁止 detail、description、error、工具输入/输出、agent 文本、调用方 URL。
深链只由服务端以对象类型、ID 和系统 `baseUrl` 生成。

L0 主动播报接收者由已映射账号与个人 scope、群 `broadcastGroupChatIds` 与群 workspace scope 求交
确定;群外事件采用无对象信息的类别级降级提示。未映射用户不收到 c3 内容。

外发确认绑定当前可外发内容与目标配置的规范化哈希;开启任一 L0 事件或目标会改变哈希,管理员重新
确认前守卫拒绝全部外发。统一外发审计区分 reply / fixed_notice / binding_notice / broadcast,
不含正文;主动播报不伪装成机器人回合。

### 「明确授权」的四重表达

宪法要求的「用户明确授权」由四条共同表达,**缺任何一条,本裁决即失效**:

- **默认关闭。** 机器人创建时一律停用,不存在「创建并启用」的一步操作。启用是一个独立的、事后的决定。
- **启用前一次不可跳过的确认。** 确认对话框逐条列出会被发往第三方云的内容范围(含已启用的 L0 事件与
  播报目标),确认动作被记下时间戳与配置哈希;服务端在启用与外发时校验,未确认或哈希过期则拒绝。
- **仅管理员。** 创建、修改、启用机器人都是外发授权决策,不是个人偏好。
- **逐次审计。** 每一次外发落一行统一外发审计(`im_outbound_audit`)。记录只留元数据与字符数——审计
  外发的**发生**,而不是把外发的**内容**再抄一份到审计表上。IM 可见正文只存在于受 ADR-0048 约束的
  有界上下文存储。`im_robot_turns` 继续表达回合生命周期,主动播报不得伪装成机器人回合。

### 出站内容守卫

外发前复用 `kernel/security` 的凭据形状检测(`detectCredentialShape`)。命中即不外发,改回一句固定的拒绝说明,
并以拒绝结果落审计;拒绝信息从不回显命中的内容。

它挡得住常见的凭据形状,挡不住任意散文——这一点必须在领域文档里明说,不能让它被读成一道语义防线。

### 与平台 SDK 的边界

第三方 SDK 只负责**入站长连接**:建立连接、维持心跳、重连、解析平台私有帧,并把事件交出来。
出站(发送消息、获取与刷新访问令牌)由 c3 自己完成,走服务端统一的出站 HTTP 通道。

这条边界不是权宜:它把 c3 会主动送出去的每一个字节都留在 c3 自己的代码里,而外发正是本裁决要
约束的那件事。一个替 c3 发消息的第三方客户端,会让上面的内容守卫与审计出现一条绕过的可能。

### 凭据处理

IM 应用密钥经既有的密钥加密落库,线上永不出现明文,读取一律打码,日志与错误信息永不含它。

这是对 C-SEC-4 的**解释而非放宽**:c3 依然不持有任何 agent 供应方的凭据。

### 无人值守会话不得挂起

机器人会话跑在一个专属的权限门下:读类工具放行,写与执行类只在预设授权且命中冻结清单时放行,尾部
默认拒绝。**面向人的交互工具(提问、计划确认)一律直接拒绝**——群聊里没有人能回答它们,放行等于制造
一条永远不回复的消息。

对结构上不支持逐工具审批的 vendor,启动期策略即门禁,不在审批桥上等待。

预设权限的默认形态是只读:一个机器人的多个会话线程共享同一个工作目录,写能力需要用户显式升级。

### 默认收敛的响应面

群消息默认必须 @机器人 才响应,单聊默认关闭。机器人不绑定工作区,按名称拥有独立工作目录,因此它
天然够不到任何已注册工作区的代码。

## Consequences

只取 SDK 的长连接换来的是不必维护一份逆向的二进制协议实现,代价是发布产物增加约 0.7 MB,以及一条
对第三方 SDK 的长期依赖。作为对照,连同其高层封装一起引入会使产物增至约三倍——该封装持有全量
OpenAPI 客户端,构建期的摇树无法削减。

代价的另一面是:平台无关的策略(@ 提及要求、入站去重、单线程串行、出站分片)必须由 c3 自己实现。
这本来就该如此——它们是每个 IM 平台都要的行为,写在中性层才能被第二个平台复用。

「只发最终文本与注册模板」让机器人无法在群里展示 agent 过程。过程包含工具输入输出,正是不该离开
本机的部分。L0 播报只携带可行动的 object 标识、标题与只读深链,表达能力 deliberately 受限。

默认只读意味着机器人首先是一个问答与查询入口,而不是一个能改代码的远程执行器。delivery 域仅有
播报与只读深链,不新增 IM 写工具。

新增一种会话类型会波及按类型正向选中的每一处(工具面、权限门、沙箱、事件订阅)。这些位置都由编译期
穷尽检查守着,遗漏会在构建时暴露而不是在运行时。

## Compliance

- 违反本 ADR 的信号:出现可绕过唯一出站守卫的 IM 发送路径;把通用 `event` 主题接入 L0 或伪造
  `im:broadcast_candidate`;外发审计记录里出现正文;机器人默认启用,或外发不校验确认哈希;非管理员能
  创建/启用机器人;面向人的交互工具在机器人门下被放行;模板携带未注册字段或自由文本;应用密钥出现在
  线上、日志或错误信息里。
- 外发的授权链与内容边界见 [im-robot](../../domains/core/im-robot/im-robot-spec.md)。
