# 0047 — 聊天机器人本地文件读取限定运行根

- **Status:** accepted
- **Date:** 2026-08-21

## Context

ADR-0046 划定了 IM 机器人「什么能外发」:只有回合结束的最终 assistant 文本。但它没有回答「机器人
能读到什么」。当时的门按工具**名**放行读类工具——`Read` 是读工具所以放行——而这个名字对「读
**哪里**」什么都没说:一个绝对路径、一串 `..`、或一个指向根外的符号链接都能让 `Read` 读到宿主机
文件,最终回答再把它背进群聊。外发边界因此绕到了「读之后、发之前」,靠出站守卫事后拦截。

这条防线有一个结构性的洞:内容只要被读过,就会出现在会话转录里——会话本身就在本机、就在 c3 手里,
而出站守卫只挡得住已知的凭据形状。真正的修复是让内容在**被读到之前**就不可达,而不是读了之后指望
过滤。

还有两层独立的缺口,同样绕不过「逐工具裁决」本身:

- 门是可跳过的。回合继承宿主机 `~/.claude/settings.json`,那里的 allow 规则在 SDK 咨询 c3 回调
  **之前**就已解析工具——宿主操作者自己的设置可以让机器人读到根外。
- 不是每个厂商的每个工具都有逐调用回调。codex 的 `shell`/`apply_patch` 没有 c3 能挂的钩子,一个
  未来的清单工具同样可能没有;它们按名称放行后,由什么来界定能触及哪里?

## Options considered

- **A. 出站守卫里加路径过滤** —— 被否决。把「读哪里」的判断推迟到外发时,内容已经进入转录;且过滤
  依赖模型把内容写出来才拦,挡不住改写、转述、摘录。
- **B. 只按工具名收紧(取消放行、默认全拒)** —— 被否决。机器人会因此失去全部读能力,连运行根内的
  合法问答都做不了;且不解决「读哪里」——一个被放行的读工具仍然能指到任意路径。
- **C. 每回合冻结运行根 + 真实路径裁决 + 双重强制边界 + 强制进程隔离** —— **选定**。一个裁决,
  两处强制执行;没有逐调用钩子的工具由进程边界兜底。详见下。

## Decision

### 单一裁决,冻结运行根

机器人回合的运行根是 `~/.c3/robots/<name>/` 的真实绝对路径,每回合启动时**冻结**一次
(`freezeRobotRoot`),根不可解析则回合以失败关闭——没有可退化的更窄边界。每次裁决先复核根仍是同一
个真实目录(被换掉的根按未建立边界拒绝)。

所有本地文件读取工具经过同一套裁决(`adjudicateRobotToolInput`):判定基于文件系统**实际解析到的路径**
(逐段 realpath,`..` 在符号链接解析之后才计算),而非字符串前缀——绝对路径、`..`、符号链接(含断链)、
相邻前缀都不构成越界通道;根外目标无论存在与否,拒绝结果一致,机器人不能拿拒绝当探针。

### 一份描述表,无默认开放

工具按 vendor 清单描述为「哪些参数是访问位置」(Claude: Read/NotebookRead/LS/Grep/Glob;Cursor:
read/ls/glob/grep/semSearch/readLints;每个位置参数区分 `location`/`glob`/`filter`)。**没有描述的
本地读工具一律拒绝**,一个新厂商工具不可能「未描述即已放行」;查询内容(如 Grep.pattern)不是访问
位置,不做无谓检查。Web/任务等不碰本地路径的读工具,以及被传输层钉死在运行根的 c3 MCP 工具,仅在
不携带未描述路径字段时放行——某天它们多出一个路径参数,当次调用即失败关闭。

### 双重强制边界

- **权限门**(`gate === 'robot'`)逐调用裁决一次。
- **执行前钩子**(Claude 的 `PreToolUse` hook)用同一裁决、同一冻结根再裁决一次。钩子先于一切规则
  (包括宿主机 `~/.claude/settings.json` 的 allow 规则)运行且**只拒绝、不代为放行**——宿主的设置不能
  绕开边界,门也不可能被钩子短路成「未经 c3 决策即放行」。

拒绝永远是同一条固定消息,不带目标路径与 errno;审计只记工具名、机器人/回合标识与拒绝原因类别。

### 强制进程隔离

机器人回合**无条件进程隔离**,与工作区沙箱开关及 `sandboxSessionKinds` 无关。门与钩子只裁决带逐调用
回调的本地读工具;厂商以无回调方式运行的写/执行工具(`shell`/`apply_patch` 及未来的清单工具)由进程
边界兜底——允许集就是机器人自己的运行根加最小厂商运行时依赖,根外数据在进程层面不可达。隔离建立
失败以安全错误结束回合,绝不退化为裸宿主机运行。

### 非机器人会话不受影响

边界是机器人专属的:work/intent/spec/spec_review/discussion/automation/tool 会话不经过本裁决,照旧
读取各自工作区。

## Consequences

机器人首先是问答与查询入口:能读到的是自己的运行根,宿主机文件即使被误指也读不到。描述表随之成为
演进闸门——厂商新增本地读工具必须补描述,否则当次调用即被拒;这是刻意的,不是缺陷。

双重执行点各付一次裁决开销,且每个机器人回合都多一次隔离启动。这是把「机器人读不到根外」从「正确
配置下成立」升级为「结构上不可能绕过」的代价。

## Compliance

- 违反本 ADR 的信号:机器人本地读解析到运行根外仍被放行(门或钩子任一);无描述的本地读工具被放行;
  拒绝消息随目标路径/errno 变化;机器人回合在无进程隔离的情况下裸跑;非机器人会话被本裁决约束。
