# im-robot — 规格

实体定义见 [im-robot-models.md](im-robot-models.md);物理接线见 [im-robot-design.md](im-robot-design.md)。

## 一条消息的判定链

平台投递一条消息后,它要通过下面每一步才会变成一次回合。任何一步不通过即静默丢弃——群里不会看到
任何反应,因为「这条消息不归我管」本来就不该产生噪音。

1. **可读性(provider 归一化)。** 只处理文本消息;缺失或空白 `senderId` 返回不可归一化——不发送回复、
   不创建 Conversation、不写回合审计。图片、文件、卡片与其它机器人的消息同样跳过。
2. **机器人仍然启用。** 每条消息都重新读取配置:管理员可能在连接建立后收紧了策略或停用了它。
3. **数据库可用。** 身份存储与机器人存储均可用;不可用时以错误回复收敛且不启动回合,不得降级到目录或厂商会话扫描。
4. **绑定控制(令牌形状)。** 私聊中的绑定验证码在普通聊天受理之前由确定性控制路径处理:认领
   `messageId` 后消费或引导,不进入模型。群内出现相同令牌**不**查询或消费挑战,只回复固定的「请在私聊完成」
   引导;群路径仍须先通过下面的响应面(未 @ 则不响应)。私聊绑定路径可跳过 `dmMode`,但出站仍走
   `binding_notice` 专用类别(见「允许外发的内容」)。
5. **身份关卡。** 已绑定发送者继续;未绑定/已撤销者认领 `messageId` 后只发送固定 Web 绑定引导,以
   `identity_required` 审计收敛,不启动 run,不读取 c3 对象。群内未绑定引导仍须先通过响应面。
6. **响应面。** 群消息:`requireMention` 为真时必须 @机器人;`chatAllowlist` 非空时群必须在其中。
   单聊:`dmMode` 为 `disabled` 即不响应,为 `allowlist` 时发送者必须在名单内(绑定控制路径除外)。
7. **不是重复投递。** 同一 `(platform, robotId, messageId)` 已认领即丢弃,不第二次运行或外发。
8. **该 Conversation 空闲。** 见下。
9. **入站持久化守卫。** 凭据形状或超过 4000 码点则不运行、不存正文,回复固定说明并以
   `input_rejected` 审计(原因 `credential` | `too_long`);拒绝信息不回显命中内容。普通代码围栏允许。

## 一个 Conversation 一次只跑一个回合

同一 `(platform, robotId, threadKey, senderId, bindingId, subject, scope_hash)` 上的回合严格串行且不排队。
忙时立刻回「上一个还在处理」,并以 `busy` 落审计(未启动 agent run)——排队会让人以为消息丢了,并发则会让两个回合争抢同一会话。
`busy` 不得记成 `blocked` 或 `error`。不同发送者的 Conversation 不共享锁,可以并发;不同线程之间也不设
并发上限,与 c3 在别处的立场一致。

## 每条被接受的消息都以回复或审计原因结束

进入回合的消息一定得到某种回复:

- 回合正常结束且有文本 → 发出该文本,投递成功后提交 Context Turn
- `input_rejected` → 固定拒绝说明(凭据或过长)
- `blocked` → 告知需要人工授权,请到 c3 中继续
- `timeout` → 告知超时已中止
- `guard_refused` → 告知内容疑似含凭据已拦下(或其它出站守卫拒绝)
- `identity_required` → 固定绑定引导(Web 发起、私聊验证)
- `scope_changed` → 告知权限已变化,请重试
- `busy` → 告知上一个还在处理
- 其它失败 → 告知出错,请到 c3 查看

无论哪种,都写一行审计。未提交回合不把用户文本或未送达回答加入后续上下文。

## 会话续接与恢复

恢复只按完整 Conversation 身份加载已提交 Context Turn:

1. 原生 `sessionId` 与 Conversation、vendor、已提交修订一致且可用 → 可续接该会话。
2. 否则启动新原生会话,以数据库已提交的 IM 可见对话为恢复种子。
3. 新的原生 `sessionId` 只回写当前 Conversation;禁止按工作目录枚举或接管会话。

服务重启后,遗留 pending 收敛为 failed 并清除原生会话缓存;发送者的新 `messageId` 可继续该 Conversation。

## 上下文保留

每个 Conversation 最多 50 个已提交回合;每个回合自提交起最多 30 天(恰好 30 天仍保留)。超出即硬删除
完整回合。删除机器人时级联清理 Conversation、上下文与审计。系统不提供跨机器人迁移、导出或延长保留。
无论哪种,都写一行审计;成功发出的固定提示也记真实 `outboundChars`。

## 外发授权

启用一个机器人就是授权数据离开本机,因此它由四条共同约束(ADR-0046),缺任何一条本裁决即失效:

- **默认停用。** 创建即停用,不存在「创建并启用」的一步操作。
- **启用前确认。** 一次不可跳过的确认,逐条列出会被发往第三方云的内容范围;确认时刻被记录。
  **服务端在启用时校验它**——前端少弹一个框不能让机器人通过。
- **仅管理员。** 创建、修改、启用都是外发授权决策。
- **逐次审计。** 每次外发落一行,只记元数据。正文只存在于受 ADR-0048 约束的上下文存储。

启用另需一个可连接的凭据;缺凭据或缺确认,启用被拒绝并给出对应原因。停用永远允许。

## 允许外发的内容

**只有一轮回合结束时的最终 assistant 文本,或已注册的固定控制提示。** 工具调用、工具结果、中间推理、
文件内容、会话转录、未注册自由文本一概不外发。固定提示分两类:

- **普通 `fixed_notice`:** 超时/阻塞/错误/忙碌/入站拒绝/存储不可用/凭据拦截等运行期提示。
- **专用 `binding_notice`:** 绑定引导、私聊引导、绑定成败与 `scope_changed`。仅可在触发该控制流程的
  原始私聊(或群内允许的 `bind_use_dm`/`identity_required`)发送;`chatId`/`senderId`/`replyTo` 必须与
  入站一致,不能改投其它聊天或冒充普通 `fixed_notice`。P2p 上可窄豁免 `dmMode`/`dmAllowlist`,其余出站
  约束(启用、外发确认、截断、审计)不变。

发出前还有两道处理:

- **凭据形状守卫。** 命中即不外发,改回固定的拒绝说明,以 `guard_refused` 落审计;拒绝信息从不回显
  命中的内容。它复用的是凭据规则,**不含**记忆域的产物规则——一个关于代码的回答理应带代码块。
- **长度截断。** 超过平台上限时截断并**明说被截断了**;数据库只保存平台确认收到的实际文本,且不超过
  4000 码点。
  所有最终回复只经**唯一出站守卫**(`sendGuarded`):supervisor 不持有可直发的 provider sender。发送前
  按固定顺序重读最新机器人事实并裁决——启用且已确认外发、目标仍是原入站聊天且仍过群/私聊白名单、
  内容类别合法、模型最终文本过凭据形状检测、全员按平台上限截断。`requireMention` 只约束入站受理,
  不扩大外发目标。凭据命中时原文不外发、不回显,改发固定拦截提示且不再对提示做凭据扫描。守卫或审计
  不可用时不得降级为原始发送。

## 无人值守会话不得挂起

群里没有人能回答授权对话框。因此机器人回合跑在一个专属的权限门下:

- 本地文件读工具只在运行根内放行(见「本地文件读取限定运行根」),不碰本地路径的读工具放行
- **面向人的交互工具(提问、计划确认)直接拒绝**——放行等于制造一条永远不回复的消息
- 写/执行类只在该机器人的冻结白名单内放行,否则拒绝
- 其余一律拒绝(默认拒绝是结构性的)

对结构上不支持逐工具审批的厂商,启动期策略即门禁,不在审批桥上等待。此外回合本身有墙钟上限,
且一旦观察到授权请求即刻以 `blocked` 收敛,不等待。三者构成三重防线。

## 本地文件读取限定运行根

机器人回合能读到的本地文件只有自己的运行根 `~/.c3/robots/<name>/`。「文件内容一概不外发」因此是
结构性的:越界内容在读到之前被拒,而非读了之后指望出站守卫拦。

- 判定基于**真实路径**,不是字符串:绝对路径、`..`、符号链接(含断链)都按文件系统实际解析结果
  裁决,相邻前缀(`<root>EVIL`)不算根内;根外目标无论是否存在,拒绝结果一致。
- 运行根每回合启动时冻结为真实绝对路径,根不可解析则回合失败关闭;每次裁决先复核根仍是同一个
  真实目录。
- 一份描述表声明各本地读工具(Claude: Read/NotebookRead/LS/Grep/Glob;Cursor: read/ls/glob/grep/
  semSearch/readLints)的哪些参数是访问位置;无描述的本地读工具一律拒绝,新厂商工具不可能未描述即
  已放行。查询内容(如 Grep.pattern)不是访问位置。Web/任务等不碰本地路径的读工具,以及被传输层
  钉死在运行根的 c3 MCP 工具,仅在不携带未描述路径字段时放行。
- **双重强制边界**:权限门裁决一次,工具执行前的钩子再裁决一次。钩子先于一切规则(含宿主机
  `~/.claude/settings.json` 的 allow 规则)运行且只拒绝,宿主的设置绕不开边界。
- 拒绝是唯一一条固定消息,不含目标路径与 errno;审计只记工具名、机器人/回合标识与拒绝原因类别。

该裁决只作用于机器人会话,非机器人会话不受影响。

## 工具权限网格

机器人回合能用哪些工具,由创建/编辑时勾选的权限网格决定。网格按当前厂商加载工具清单
(SDK 内建工具 + c3 自己的 MCP 工具),按「只读 / 写入」两组呈现,带全选与全清。两条原则:

- **创建默认只读。** 新建时只勾只读类工具,写入/执行类不勾,`network-access` 关闭。
- **编辑保持原样。** 编辑时回读已存的白名单并原样勾选;清单加载失败或为空时网格显示空态,
  但**不会把已保存的白名单清成空网格**。

**切换厂商会清空上一个厂商的勾选**——一个厂商的工具名不会残留到另一个厂商下。清单加载失败不提供
自由文本兜底:网格没有文本框。

### `network-access` 伪条目

`network-access` 不是一个工具,而是随白名单一起存储的能力开关(同样出现在 allowlist 里),永远不进入
门禁/放行集合,也不参与全选/全清。语义:

- **仅 Codex + workspace-write 沙箱生效**:打开它只允许 codex 的 shell 命令出网。
- 它**不授予 shell 本身**,也不启用 web 搜索。
- 默认关闭。只读沙箱下开关置灰并解释(该沙箱无条件禁网);切回可写沙箱时,已存值保留。
- 没有网络旋钮的厂商(claude 等)静默忽略——不渲染开关,残留的存量值不影响启动也不扩大能力。

### 机器人回合的沙箱推导

Codex 原生沙箱模式**只**由 SDK 本地写/执行工具决定:勾了 `shell` / `apply_patch` 之一即为
workspace-write,否则只读。勾选 c3 MCP 写工具(如 `mcp__c3__save_intents`)**不**算——它跑在 c3
服务端自己的域守卫之后,绝不能成为打开可写沙箱(进而打开网络边界)的理由。

机器人回合还**无条件进程隔离**,与工作区沙箱开关和 `sandboxSessionKinds` 无关。门与钩子只裁决带
逐调用回调的本地读工具;厂商以无回调方式运行的写/执行工具(`shell`/`apply_patch` 及未来的清单工具)
由进程边界兜底——允许集就是机器人运行根加最小厂商运行时依赖,根外数据在进程层面不可达。隔离建立
失败以安全错误结束回合,绝不退化为裸宿主机运行。

### c3 MCP 工具按回合绑定

勾选的 c3 MCP 工具按线程经回环 HTTP MCP 绑定到机器人运行目录(`~/.c3/robots/<name>/`),只暴露勾选的
子集:未勾选工具既不出现在 tools/list,直接调用也被拒绝。与自动化 MCP 不同,机器人 c3 工具**不在连接时
钉定单一工作区**:六个 L1 只读工具在每次 handler 执行时重新读取 active binding、`user_workspace_scopes`
与群白名单并求交;对象型工具由 id 反查工作区,列举型在全部个人 scope 内枚举并标注 `workspaceName`。
写类 c3 工具不能借对象 id 反查获得工作区路径。本地文件读取仍只限于运行根,二者互不替代。

## 与工作区的关系

机器人是**部署级** IM 出入口,不是工作区资源:配置与名册跨工作区一致,运行目录
`~/.c3/robots/<name>/` 不进工作区注册表。因此:不出现在工作区切换器、不出现在会话页、其 run 不会
唤醒为本机开发流程配置的自动化(机器人会话种类需被自动化显式点名才参与匹配)。

部署级全局 ≠ 无边界访问。目录、连接、`threadKey`、`sessionId` 都不构成工作区授权;涉及 c3 对象的
能力必须在每次工具调用时重新求交。否决「每工作区一个机器人」以及「为连接或线程固定工作区」——
线程级绑定会把一次上下文选择变成后续调用的隐形授权。

一个机器人的多条 Conversation 共享同一个工作目录。当前只保证同 Conversation 串行,因此跨发送者并发
写同一目录是可能的——这正是预设权限默认只读的原因之一。

## 能力上限 L0–L3

对 c3 领域数据与业务动作的能力天花板(不替代运行层工具权限):

- **L0 播报** —— 受控通知,只允许注册事件与固定模板;本实现不启用主动播报
- **L1 只读问答** —— 用户发起的只读查询,每次调用重算作用域;当前仅保留已安全可达的只读行为
- **L2 定向作答** —— 仅对已指定 actor 与允许答案集合的待办做确定性回应;本实现不提供
- **L3 重动作** —— 开发启动、设置修改、删除、交付/PR 等不在 IM 内执行,只回 Web 深链

该分级不是启用开关;现有默认停用、启用前确认、只读默认与出站守卫基线保持不变。
