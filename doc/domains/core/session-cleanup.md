# Domain: session-cleanup

- **Group:** core
- **One-line:** 按工作区保留期删除 c3 历史会话,并提供独立的全局厂商存储清理。
- **Owner:** maintainer
- **Status:** active
- **Depends on:** [workspace-setting](../settings/workspace-setting.md)(工作区保留期);[system-setting](../settings/system-setting.md)(全局清理);[session-registry](session-registry.md)(会话归属);[sandbox](sandbox.md)(厂商存储)。
- **exposes-api:** false

本域负责过期会话的周期清理,不拥有会话内容或业务实体。

## 工作区会话保留

每个工作区可独立修改会话保存天数,默认 15 天、最少 1 天,取整数天。服务启动后延迟执行首次清理,此后每日批量执行,配置修改无需重启。

只选择已登记工作区内 c3 已绑定的会话,涵盖自动化等各类历史会话。保留期从最后活动时间计算;运行中的会话跳过,原生转录或子会话最近仍有写入的也保留。删除前重新核对活动与当前设置,避免扫描期间的续跑或保留期调整误删。

过期时删除原生转录和 c3 会话列表记录、会话级设置与沟通索引,释放空闲运行时。自动化任务、执行日志、意图和讨论等业务记录保留。删除后的历史内容不能回放或继续。Cursor IDE 会话不在清理范围内。

工作区保留设置只约束 c3 登记的会话,不依据目录归属清扫用户在外部工具中创建的会话。

## 全局厂商存储清理

系统级开关独立于工作区策略,默认关闭。开启后按全局保留期清理可达厂商存储中的过期文件,包括非 c3 会话;缺省保留 30 天、最少 1 天。全局策略可能先于工作区保留期删除转录。

厂商存储按共用约定识别,覆盖隔离 home 与宿主 home,不受工作区沙箱开关影响。只清理会话存储内部,不删配置、凭证、技能或状态库,不碰 Cursor IDE 会话库。能力边界见 [agent-session](agent-session.md#cursor-能力边界)。

## 执行与失败

两种策略均随服务启停、按日执行。工作区清理不重叠运行。扫描失败保留对应厂商的会话,单会话删除失败记录后继续处理其余会话,不拖垮服务。缺失转录的过期 c3 列表记录同样可回收。
