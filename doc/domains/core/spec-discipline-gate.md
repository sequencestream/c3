# 规格纪律升级门槛

规格撰写与审核纪律当前**只告警、不阻断**。这份文档说明它凭什么只能是告警，以及四条指标各自测到什么、门槛如何判定。

## 为什么是告警

三条依据，都与存量样本量无关：

1. **零对照基线**。四项指标在新规则生效前从未被测量。没有旧规则下的分布，就没有「耗时下降 ≥15%」的参照点，只能先影子运行建立分布。
2. **检测器未经验证**。误报率是门槛四项之一。一个未在真实流量上跑满一轮的检测器，没有资格阻断任何流程。
3. **历史分布不支持收紧**。259 条审核结论（覆盖 162 个意图，采集于 2026-10-05）中 94 条为需修改，返工轮次分布 0/1/2/3/4 = 977/46/17/2/2，打满上限的仅 4 个意图。收紧引入的误伤，代价落在本就稀少的轮次预算上。

存量样本量**充足**（规格根下 256 份），不构成提前阻断的理由。

## 四项指标

| 指标         | 口径                                                               | 现状基线   |
| ------------ | ------------------------------------------------------------------ | ---------- |
| 中位评审耗时 | 同一意图从规格 `pending` 到收到审核结论的时长中位数                | 待盲评测得 |
| 复述准确率   | 评审者只看规格时复述出的动机 / 变更 / 边界与规格实际内容一致的比例 | 待盲评测得 |
| 边界遗漏     | 规格中缺失、且开发时会被迫自行发明的决策条数                       | 待盲评测得 |
| 告警误报率   | 告警表中被判为误报的命中数 / 命中总数，按规则 id 聚合              | 待盲评测得 |

前两项与后两项都**不能**从磁盘与账本回填——存量数据里没有旧规则下的行为记录。基线脚本只采集可回填的四项存量事实（文档总数、含交接节的文档数、批准意图数、审核结论与返工轮次分布），其余靠盲评。

## 盲评设计

- **样本**：12–20 个意图，从 256 份存量中按档位分层抽取，覆盖简单 / 普通 / 复杂三档。
- **时间分布**：跨三个月分布（7 月 91 / 8 月 127 / 9 月 34 / 10 月 4），避免只取近期样本。
- **交叉**：≥2 名评审独立打分，同一份规格的新旧规则两版结果分别记录。
- **盲**：评审者不知某份文档适用的是新规则还是旧规则。

## 升级判据

四项**同时**满足，才把「重复规范事实」与「导航冒充约束」升级为阻断：

```
median_review_minutes_new  <= median_review_minutes_old * 0.85
restate_accuracy_new      >= restate_accuracy_old
boundary_omissions_new     <= boundary_omissions_old
false_positive_rate        <= 0.10
```

**句长类规则永久只告警**，不参与阻断判定——它没有数值阈值可供判定，只有形态描述。

未达门槛前，全部规则的告警状态在代码与文档中都不得被改写为规范。

## 度量的通道

告警不进入提示词、不改变会话行为，落库是唯一通道：写入失败只告警，会话启动照常成功。误报率的分子分母直接由告警表按规则 id 聚合得出。
