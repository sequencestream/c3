# Project — c3 (Code Creative Center)

## 愿景

c3 是一个本地优先的 **AI 工作台**，通过统一的浏览器控制面集中管理、驱动和监督多个
AI coding agents。它让人能够跨工作区组织智能体完成从讨论、意图和规格到开发、评审与交付的
完整工作，同时始终看得见运行状态、权限决策和最终结果。

c3 面向统一的智能体抽象，而非某一家厂商的产品形态。当前支持 Claude Code、Codex 和 Cursor，
并通过 vendor 中立的适配与能力声明接入未来的智能体运行时。

## 问题

AI coding agents 通常运行在不同的终端、厂商工具和项目目录中。会话上下文、权限提示、执行状态和
研发进度彼此割裂，人难以同时监督多个智能体，也难以把一次对话稳定地推进为可追踪、可评审、
可交付的工作。

c3 将人的控制面与各 vendor 的执行面解耦：浏览器集中承载工作组织、状态观察和人工决策，本地
服务通过统一适配层驱动不同运行时，并把各自的能力差异如实呈现给上层工作流。

## 范围

**范围内**

- 通过统一控制面管理多个工作区、会话、智能体和并发运行。
- 通过 vendor 中立适配层驱动 Claude Code、Codex、Cursor 及后续接入的智能体运行时。
- 按 vendor 的实际能力提供权限策略、人工审批、人机问答、运行控制和明确的能力降级。
- 组织讨论、意图、规格、开发、评审、PR、交付与自动化形成可追踪的研发闭环。
- 在本地持久化工作区、配置和业务状态，并从 vendor 原生会话存储读取对话记录。
- 通过浏览器、桌面壳、外部 MCP 与聊天机器人提供受同一授权边界约束的交互入口。
- 将 c3 应用自身交付为可自托管的单一二进制。

**范围外（非目标）**

- 不提供由项目方运营的云端 SaaS 或通用多租户平台。
- 不替代 vendor 的账号、订阅、认证、模型服务或原生 CLI；智能体凭据仍归对应 vendor 所有。
- 不假定所有 vendor 具备相同能力，也不通过伪造兼容性掩盖逐工具审批、会话控制等能力差异。
- 不把 vendor CLI 打包进 c3 应用二进制；可管理的 CLI 与使用方自行安装的 CLI 都属于外部运行时。
- 不替代 Git、代码托管平台或 vendor 原生会话存储。

## 用户与相关方

- **本地开发者**：创建和监督智能体工作，在需要时作出决策并检查结果。
- **工作区操作者**：管理讨论、意图、规格、自动化、PR 与交付流程。
- **管理员**：配置账号、智能体、vendor 运行时、沙箱、工作区权限和外部接入。
- **外部集成调用方**：通过 MCP 或聊天机器人使用授权范围内的 c3 能力。
- **维护者**：维护统一协议、业务领域、vendor 适配层、服务端和客户端。

## 成功标准

- 用户能够从一个控制面创建、观察、继续、停止和恢复不同 vendor 的智能体会话。
- 敏感操作始终受已声明的权限策略约束；vendor 能力不足时明确降级，不伪造安全保证。
- 用户能够把讨论或想法推进为意图、规格、实现、评审、PR 和交付，并持续看见每一步的状态。
- 多个工作区和会话能够并发运行；浏览器重连或服务重启后，持久化的工作状态仍可恢复。
- 某个 vendor 缺失或运行失败不会阻止其他可用 vendor 工作，错误和能力缺口会明确呈现。
- 接入新 vendor 主要发生在适配器、能力声明和注册入口，核心协议与业务编排不按厂商分叉。
- c3 保持本地优先；工作数据默认留在本地，智能体凭据继续由对应 vendor 管理。

## 交付形态

c3 以本地服务运行，提供浏览器控制台和桌面壳。应用自身可构建为单一二进制；智能体运行依赖
对应 vendor 的宿主 CLI，其中部分 CLI 可由 c3 管理，其他 CLI 由使用方安装。

系统配置、工作区注册表和业务状态保存在实例对应的本地数据库中。会话正文仍以各 vendor 的原生
存储为事实来源，c3 通过统一会话接口读取和恢复。
