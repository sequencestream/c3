# 风格设计规范

## 1. 设计原则

- **极致沉浸**：界面退后，内容向前。去除一切不必要的分割线、边框和装饰。
- **轻量透明**：大量使用半透明材质、弥散阴影和柔和圆角，营造轻盈的现代感。
- **顺畅直觉**：动效细腻且有意义，所有交互反馈都自然、不打断心流。
- **冷峻科技**：色彩以冷静的深色为基底，点缀高饱和但克制的强调色，传递智能与可靠。
- **密度适中**：信息密度低于传统 IDE，留白充裕，减少认知负荷，适合长时间使用。

## 2. 视觉基础

### 2.0 主题注册表

主题是**可扩展的注册表**，不是页面里的二选一开关。注册表每项声明一个主题的稳定 id、展示名称（走 i18n，主题名是普通 UI 文案）与其 `color-scheme`；界面上的主题选择器由注册表直接生成，不另存一份主题清单。

主题只映射不配色：运行时把选中的 id 归一后写入根元素的 `data-theme`（与该主题的 `color-scheme`），配色取值仍全部留在设计令牌里。默认主题 `dark` 的令牌挂在 `:root`；其余主题各自一个 `:root[data-theme='<id>']` 覆盖块（当前只有 `light`，取值见 2.1 与 `web/src/standard.css`）。未知、缺失或损坏的值先归一为 `dark`，任意字符串不会进入 DOM。

因此新增一个预设主题 = 注册表加一项 + 加一组同名的 CSS 变量覆盖块，无需改动选择器或运行时。

主题选择是显式的个人化设置（见 [personalized-setting 规范](../domains/settings/personalized-setting/personalized-setting-spec.md)的 `theme` 字段），按账户级 / 浏览器本地存储；不读 `prefers-color-scheme`，不做跟随系统的自动切换。

> 未走 `--c-*` 令牌的硬编码颜色在非默认主题下会显形，按普通缺陷单独修复，不由主题机制兜底。

### 2.1 色彩系统（暗色模式为主）

| 用途            | 色值                       | 说明                                  |
| --------------- | -------------------------- | ------------------------------------- |
| 页面主背景      | `#18181B`                  | 较深的灰黑，避免纯黑刺眼              |
| 侧栏/面板背景   | `#1F1F24`                  | 稍亮，与主背景形成层次                |
| 悬浮卡片背景    | `#27272D`                  | 用于下拉、弹窗、消息卡片              |
| 输入框背景      | `#2C2C33`                  | 可轻微带透明 `rgba(255,255,255,0.05)` |
| 边框分割线      | `#3A3A42`                  | 极淡的描边，只在必要时出现            |
| 主文本          | `#E4E4E7`                  | 高可读性浅灰白                        |
| 次要文本        | `#A1A1AA`                  | 辅助说明、占位符                      |
| 禁用文本        | `#6B6B75`                  | 不可用状态                            |
| 强调色 Primary  | `#6366F1` (靛蓝)           | 按钮、选中、焦点                      |
| 强调色渐变      | `#6366F1` → `#A855F7` (紫) | 品牌标识、AI 相关、主按钮             |
| 成功            | `#22C55E`                  | 状态成功、代码运行通过                |
| 警告            | `#F59E0B`                  | 提醒                                  |
| 错误            | `#EF4444`                  | 报错、删除                            |
| AI 助手信息背景 | `#2D2D5E` (半透明)         | 带靛蓝底色的卡片，体现智能            |
| 用户消息背景    | `#3C3F6B` (半透明)         | 偏蓝紫，区分对话方向                  |

亮色模式（注册表中的 `light` 主题）沿用同一组基础色相，将背景映射为 `#FFFFFF`、`#F8F8FC` 等；完整取值以 `web/src/standard.css` 的 `:root[data-theme='light']` 块为准，本节不重复列举。浅色覆盖块遵循两条规则：

- **文字三档按实际背景重新取值**：主文本、次要文本、禁用文本各自与真实承载它们的背景（页面、面板、输入框、代码块、两类对话气泡及悬停叠加态）比对，满足第 6 节门槛，而不是只在纯白上测一次。次要文本承载说明、路径、时间等真实信息，按正文门槛处理。
- **状态与强调色分基色与深一档变体**：`--c-primary` / `--c-success` / `--c-warning` / `--c-error` / `--c-info` 等基色用于装饰性的填充、描边与图示；`--c-*-text` 变体用于需要自己挣得对比度的位置——浅底上的前景文字，以及必须托住白字的实底。暗色下变体与基色同值，浅色下整体下沉。一个取值托不住深浅两种底色，这是拆分的唯一理由。

固定色只在两个主题下底色相同时才成立：白字压主色 / 危险色实底、深墨压警告色实底。其余文字色一律走 `--c-*` 令牌。

`web/src/lib/contrast.ts` 提供 WCAG 相对亮度与对比度计算（含半透明叠加的合成），`contrast.test.ts` 逐对断言审计清单与门槛，并静态拦截新出现的主题敏感硬编码文字色。

### 2.2 字体排印

- **UI 字体**：系统 UI 栈，末尾补 CJK 回退 `…, Inter, "Noto Sans SC", "Noto Sans JP", "Noto Sans KR", "Noto Sans", sans-serif`
- **代码字体**：`"JetBrains Mono", "Fira Code", "Cascadia Code", ui-monospace, "Noto Sans SC", "Noto Sans JP", "Noto Sans KR", "Noto Sans", monospace`
- **CJK 防 tofu**：在通用兜底（`sans-serif` / `monospace`）之前追加 `Noto Sans SC/JP/KR + Noto Sans`，使缺 CJK system font 的环境逐字回退到 Noto 而非渲染豆腐块（□）。`SC` 优先（汉字统一码下 zh 字形优先）。仅追加字体名、不自托管 web 字体。五语均非 RTL。
- **字号比例**（以 16px 为基准）：
  - 标题大：20px / 1.3
  - 标题小：16px / 1.4，`font-weight: 600`
  - 正文：14px / 1.5
  - 辅助说明：12px / 1.5
  - 代码：13px / 1.6

### 2.3 多语言长字段防溢出

CJK 无空格断词 + 长 token（路径 / URL / ID）易溢出或被裁剪。全局样式基线提供两类可复用的长字段处理能力，长字段按需引用：

- **单行截断**：单行裁剪并以省略号收尾（`min-width:0; overflow:hidden; white-space:nowrap; text-overflow:ellipsis`），容器须可收缩。
- **任意位置换行**：多行换行（`min-width:0; overflow-wrap:anywhere; word-break:break-word; line-height:1.5`），任意位置断行（含 CJK 与超长无空格 token）。

> `overflow-wrap:anywhere` 仅限上述可复用能力内，不做全局，避免破坏 flex 布局。

### 2.4 间距与圆角

- **基础单位**：4px
- **内边距**：常用 8px, 12px, 16px, 24px
- **组件间距**：8px / 12px / 16px
- **页面留白**：最小 16px，最大 32px
- **圆角**：
  - 小组件（按钮、输入框、标签）：8px
  - 卡片、面板、对话框：12px
  - 大型面板、侧栏：16px
  - 圆角按钮/胶囊：全圆角（`9999px`）

### 2.5 阴影与层级

不依赖实色边界，用阴影和透明度区分层级：

- **低层级（悬浮卡片）**：`0 2px 8px rgba(0,0,0,0.3), 0 0 1px rgba(255,255,255,0.06)`
- **中层级（对话框、面板）**：`0 8px 24px rgba(0,0,0,0.4), 0 0 1px rgba(255,255,255,0.08)`
- **高层级（通知、工具提示）**：`0 12px 32px rgba(0,0,0,0.5)`

背景模糊：面板/浮层使用 `backdrop-filter: blur(16px)` 配合半透明背景。

## 3. 核心组件规范

### 3.1 全局布局

- **结构**：左侧图标式一级导航（48px 宽）→ 二级侧栏（240px 宽）→ 主内容区（剩余宽度）→ 右侧辅助面板（可选）。
- **顶部**：轻量标题栏，高度 44px，含窗口控制按钮和项目名称。
- **底部**：状态栏，高度 28px，显示当前光标位置、分支等，用更小字号和弱化颜色。

### 3.2 图标式一级导航（Activity Bar）

- 宽度 48px，背景 `#1A1A1E`。
- 图标尺寸 24px，颜色 `#888`，激活时变为强调色，并出现左侧 2px 宽彩色指示条（`#6366F1`）。
- 图标容器圆角 8px，激活背景为 `rgba(99,102,241,0.15)`。
- 底部放置设置、账户等系统图标。

### 3.3 侧栏/面板

- 背景 `#1F1F24`，头部分隔采用极浅的底部边框 `1px solid #3A3A42`。
- 列表项：高度 36px，左右内边距 12px，圆角 6px。悬停背景 `rgba(255,255,255,0.05)`，选中背景 `rgba(99,102,241,0.12)`。
- 滚动条：宽度 6px，滑块圆角，颜色 `rgba(255,255,255,0.15)`，悬停变亮。

### 3.4 对话界面（Chat Panel）

核心交互区域，设计突出“与 AI 自然对话”。

- **消息列表**：上下内边距 16px，消息项间距 24px。
- **AI 消息气泡**：
  - 背景 `#27272D`，圆角 12px，左对齐，带内边距 16px。
  - 可以无显式头像，或用简约 AI 标识（如六边形图标）。
  - 代码块使用更暗的背景 `#1B1B20`，圆角 8px，内边距 12px，配有语言标签和复制按钮。
- **用户消息气泡**：
  - 背景为 `#3C3F6B`，圆角 12px，右对齐。
- **输入区域**：
  - 位于底部，背景 `#1F1F24`，上边框 `1px solid #3A3A42`。
  - 输入框背景 `#2C2C33`，圆角 12px，聚焦时边框 `1px solid #6366F1`，阴影 `0 0 0 2px rgba(99,102,241,0.3)`。
  - 内置发送按钮，无边框背景，图标颜色随内容变化（空输入时弱化，有输入时强调色）。

### 3.5 按钮

#### 尺寸模型

全局 `button` 的默认尺寸不再硬编码固定高度，而是采用「文字高度」基线：`line-height: 1` 配合适度上下内边距（`padding: var(--sp-2) var(--sp-6)`，即上下 8px、左右 24px），高度由内容撑开（在正文字号下约 30px），宽度由内容撑开（不再设 `min-width`）。这是站内绝大多数按钮的合理默认值；需要更大或更紧凑尺寸的按钮按需显式声明高度，而非依赖全局默认。

- **页脚大按钮**：发送、停止、麦克风按钮显式声明 `height: 56px`，与 56px 高的输入框对齐。
- **紧凑场景**：按需显式声明高度——权限决策按钮 / 设置页底部按钮 / 加 agent 按钮为 36px；侧边栏图标按钮 22px（方形），侧边栏行内按钮 30px / 24px。这些是有意的尺寸声明（自身使用零上下内边距，需显式 `height`），非对抗默认值的复位。

> 历史说明：本规范 3.5 节曾记「主按钮高度 36px、内边距 0 20px」，与改动前实际代码的 `height: 56px; min-width: 80px;` 默认值并不一致；该 56px 默认又迫使全站多处按钮写 `height/min-width` 复位来对抗。2026-05-30 的全局 `button` 重构将默认回归文字高度、把 56px 还原为页脚大按钮的专属尺寸，并清理了对抗性复位，本节描述同步澄清了这一历史不一致。

#### 类型样式

- **主按钮**：背景使用渐变 `linear-gradient(135deg, #6366F1, #A855F7)`，文字白色，圆角 8px，悬停亮度提升，按下缩放至 98%。
- **次按钮**：背景 `rgba(255,255,255,0.08)`，文字 `#E4E4E7`，悬停 `rgba(255,255,255,0.12)`。
- **幽灵按钮**：透明背景，文字强调色，悬停背景 `rgba(99,102,241,0.1)`。
- **危险按钮**：背景 `#EF4444`，文字白色。
- **禁用态**：整体透明度 0.4，光标 default。

### 3.6 输入框与选择器

- 高度 36px，背景 `#2C2C33`，圆角 8px，内边距 0 12px，边框 `1px solid #3A3A42`。
- 占位文字 `#6B6B75`。
- 聚焦：边框 `#6366F1`，外发光 `0 0 0 2px rgba(99,102,241,0.25)`。
- 错误状态：边框 `#EF4444`，外发光对应红色。

#### 原生表单控件基线

同一份界面既跑在浏览器里，也跑在桌面壳的系统 WebView（macOS 上是 WKWebView）里，而原生控件的默认外观与度量在 Blink 与 WebKit 之间并不相同：默认字号、复选框外边距、下拉框被强制的内边距与圆角、`<input>` 由默认 `size` 得到的固有宽度，都各算各的。任一处漏出默认值，同一行控件就会在两处排出不同宽度乃至整行错位。基线因此在 `web/src/standard.css` 把外观与度量收归样式表，只做归一，控件皮肤仍由各站点定义：

- 字体与字号继承正文，不取各引擎的控件默认值。
- `<input>` / `<select>` 的 `min-width` 归零，固有宽度不再顶穿显式的 `width` / `flex-basis`。
- 复选框与单选钮取对称外边距，选中色为强调色。
- `<select>` 用 `appearance: none` 接管外观，箭头以两段渐变按 `currentColor` 画出，右侧留出 `--sp-select-arrow`。站点若用 `padding` 简写覆盖基线，自行补回右内边距；背景用 `background-color` 而非 `background` 简写，简写会连带清掉画在背景上的箭头。
- 滑块自绘轨道与滑钮，已拖过的一段由站点写入 `--range-fill` 上色——`accent-color` 只有 Blink 会用来填充轨道。

原生下拉展开后的浮层由系统绘制，不受基线约束；符号与 emoji 图标的字形宽度同样由引擎的字体回退决定，两处相差数像素。

#### 标准下拉框（Dropdown）

需要定制浮层的场景采用标准自定义下拉组件；其余用原生 `<select>`，外观由上述基线归一。结构为「触发按钮 + 浮层面板」：

- **触发按钮**：以 `<div role="button">` 实现（不用 `<button>`，避开全局主按钮样式污染高度），高度由内容撑开。（历史背景：该规避动机源于当时全局 `button` 默认 `height: 56px`；自 3.5 节按钮重构后全局默认已改为文字高度、高度污染显著弱化，此规避的成因已缓解，但当前实现保持现状不强制回归 `<button>`。）背景 `#2C2C33`，边框 `1px solid #3A3A42`，圆角 8px；右侧带下拉箭头，展开时旋转 180°。悬停边框变亮、背景升一级（`#27272D`）；展开时边框为强调色并带外发光 `0 0 0 2px rgba(99,102,241,0.25)`；禁用态透明度 0.5。
- **浮层面板**：背景 `#1F1F24`，圆角 12px，中层级阴影，内边距 4px；相对触发按钮定位（默认向下，可向上），层级置于内容之上；最大高度约 320px 后内部滚动。出现动画为上移淡入（150ms）。
- **选项行**：左对齐，可选行首图标（次要色）+ 标签，行尾对当前选中项显示 `✓`（强调色）；圆角 8px，内边距 8px 12px。键盘/悬停高亮（active）背景 `rgba(255,255,255,0.08)`；当前选中项文字为强调色；禁用项透明度 0.4。
- **交互**：支持键盘导航（`↑`/`↓` 移动、`Enter`/`Space` 选定、`Esc`/`Tab` 关闭）、点击外部关闭；`role="listbox"` / `role="option"` 与 `aria-selected` 等无障碍语义。

### 3.7 工具提示（Tooltip）

悬停提示统一用原生 `title` 属性，由浏览器/系统渲染，不自建浮层：提示内容是补充说明而非交互内容，换取零维护成本与系统一致的行为。因此它不受设计令牌与主题控制，也不参与配色审计；需要可交互、可换行或需要样式的提示，用下拉浮层或对话框承载。

### 3.8 弹窗与对话框（Modal / Dialog）

- **默认宽度 = 页面宽度的二分之一**（桌面端 `width: 50vw`）。这是系统级默认约束：新弹窗不再各自拍脑袋定尺寸，一屏之内多个弹窗的体量彼此可比。
  - 只需再配一对上下限兜住极端视口：超宽屏不被拉成长条（`max-width`），窄屏不被挤没（`min-width`）。上下限是保护栏，不是对默认值的替换。
  - 这是**默认值而非铁律**：有正当理由的弹窗可显式声明自己的宽度并在组件里写清理由——短确认框（`ConfirmDialog`）、单行输入（`InputDialog`）、错误提示（`ErrorDialog`）这类内容天然短的弹窗，用比半屏更窄的固定宽度反而更好读。约束新立，既有弹窗的现有尺寸不追溯调整。
- **移动端（`max-width: 767px`）一律退化为全屏 sheet**：`width: 100vw`、`max-width: none`、`min-height: 100dvh`、去边框与圆角，页脚按钮吸底（`margin-top: auto`），并按 `env(safe-area-inset-*)` 留出安全区。此时宽度规则由 sheet 接管，默认宽度不再适用。
- **交互契约**（与 `ConfirmDialog` 一致）：受控组件（父持 `open`）、遮罩点击 / Esc / 取消按钮一律等价于取消、取消不写回任何字段、每次打开以当前数据重新预填。

### 3.9 标签与徽章

- 圆角 6px，内边距 2px 8px，背景 `rgba(255,255,255,0.08)`，文字 11px。
- 状态标签：如 AI 生成使用紫色背景 `rgba(168,85,247,0.15)`，文字 `#C084FC`。

## 4. 动效规范

- **缓动曲线**：使用 `cubic-bezier(0.4, 0, 0.2, 1)` 实现标准缓动，弹性组件可用 `cubic-bezier(0.34, 1.56, 0.64, 1)`。
- **时长**：
  - 悬浮/聚焦过渡：150ms
  - 面板展开/收起：250ms
  - 模态框出现/消失：200ms，带缩放 + 淡入
  - 列表项进场：交错延迟 30-50ms，避免僵硬。
- **特点**：面板滑入采用 100% 不透明度配合 `translateY(4px)` 到原位，强调向上浮现的感觉。对话消息采用自底部向上淡入，新消息平滑滚动到底。

---

## 5. 图标风格

- 使用 24px 线性图标，笔画宽度 1.5px，端点圆润。
- 常用图标库：Lucide、Phosphor，风格清瘦、统一。
- 色彩遵循前景色规则，通常 `#A1A1AA`，激活/悬停时变色。

---

## 6. 可访问性（最低要求）

- 文本与背景对比度至少 4.5:1（正文与承载信息的次要文字），大号文字及确属辅助层级的文字 3:1。对比度按浏览器最终合成色计算：半透明底、叠加态与 `color-mix()` 先合成再比。
- 禁用文字同样不低于 3:1；禁用状态由透明度、光标与控件状态表达，不靠压低前景色对比度来传达。
- 所有交互元素有清晰的焦点指示器（2px 强调色外框，偏移 2px）。
- 支持 `prefers-reduced-motion`，减少或禁用非必要动效。
- 提供亮色模式变量切换，通过 CSS 自定义属性实现，由用户在个人化设置中显式选择（见 2.0）。
