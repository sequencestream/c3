# 交付（Delivery）

一批意图共同集成并进入主线。意图回答「这一条要做成什么」；交付回答「这几条一起合进哪条分支、谁来验证、何时上主线」。c3 从不代合主线。

> 建议先阅读[从需求到意图](requirement-to-intent.md)。交付建立在工作树模式上：当前分支模式下仍可查看与关联，但不能初始化交付分支或建交付 PR。

---

## 一、为什么需要交付

多个意图可以并行开发，各自有工作树和 PR。若每条 PR 都直接打向主线，集成顺序、互相覆盖和「这一批能不能一起上」只能靠人在托管平台上记忆。交付把这批意图收成一个 Git 生命周期单元：

- 一条交付分支，意图 PR 打向它而不是主线；
- 守卫按顺序推进：分支就绪 → 关联意图的 PR 均已合入 → 人工确认验证 → 交付 PR 合入主线；
- 验证期间关联意图不得再开写入会话，避免一边验一边改。

不适合建交付的情况：多仓工作区（服务端拒绝）、只改当前检出、或本来就要每条意图独立合进主线。

---

## 二、在 c3 里怎么用

### 状态

`planned`（规划）→ `integrating`（集成中）→ `verifying`（验证中）→ `verified`（已验证）→ `delivered`（已交付）。非终态可取消。没有单独的「已完成」——关联 PR 合入交付分支的进度以实时 N/M 呈现。

### 前置条件

- 已完成 [c3 入门指南](c3-get-start.md)中的安装与启动，工作区为工作树模式；
- 已有至少一条意图，或准备在创建意图时直接选这个交付作基准。

### 典型路径

```
创建交付（快照当时的主线为 baseBranch）
   → 初始化交付分支（从远端主线 tip 分叉；远端已有同名且起点一致则绑定）
   → 关联意图（或在意图侧一键建专属交付）
   → 各意图 PR 打向交付分支并合入
   → 开始验证（写入窗口关闭）→ 人工确认验证
   → 建交付 PR（交付分支 → 主线）→ 你在托管平台合并
   → 已在主线则标 delivered
```

1. **创建。** 顶栏进入交付页，新建一条。创建时快照工作区当前主线为基准，之后改工作区配置不回写。多仓工作区不能建交付。
2. **初始化分支。** 与创建分步。只取远端主线 tip，不取本地引用。落后主线只警告。终态不自动删远端分支；清理只删本地引用。
3. **关联意图。** 交付页与意图侧都可以关联。关联是独立边，不改投已有 PR。对本交付已合并的 PR 禁止解除；解除未合并须先关掉那条 PR。意图侧可一键建专属交付、关联并初始化分支；任一步失败停在该步，已完成部分保留。
4. **集成。** 分支就绪后方可进入集成。集成期间可把主线合入交付分支，冲突不代解、不推送。
5. **验证。** 至少一个关联意图、且其对本交付的 PR 均已合入，才能开始验证。验证中禁止新的写入会话。人工确认后进入已验证。
6. **交付 PR。** 已验证、分支就绪、相对主线有差异时，建一条到主线的 PR。c3 不代合、不自动关旧 PR。托管已合而本地未确认时显示等待，进页或手动再同步；已在主线则直接标交付。冲突回退到验证中。

角标只计需人处理的交付（可解缺口、可推进、或可执行的交付 PR 动作），纯等待与终态不计。

### 与意图、自动化的关系

- 新建意图时可把基准选成一个仍可写入的交付（规划 / 集成中，且分支已就绪）。
- 生命周期事件（`delivery:created` 等）可供自动化订阅；自动化与外部只能只读查询交付，没有写工具。

### 常见问题

**Q：交付和意图 PR 有什么区别？**

A：意图 PR 是「这一条意图的代码怎么进交付分支」；交付 PR 是「这一批已经验证过的结果怎么进主线」。合入主线只走交付 PR，且由你在托管平台合并。

**Q：当前分支模式下能用交付吗？**

A：可以创建、查看、编辑、取消、关联并看进度，不能初始化分支，也不能建交付 PR。

**Q：验证开始后还能改代码吗？**

A：验证中或终态的交付不再开新的写入会话；已经在跑的挂接不受影响。要改就返工回到集成中。
